1. System Overview
1. System Overview
The Examic Evaluation System is a multi-mode academic examination management and evaluation platform. It supports three primary evaluation workflows:
Mode
Mode
What it is
What it is
OSM (OnScreen Script
OSM (OnScreen Script
Marking)
Marking)
Physical answer scripts are scanned 
→
 distributed to evaluators 
→
 marked
online
Data Entry
Data Entry
Faculty manually enters marks for paper-based exams (no scanned scripts)
CBT (Computer-Based Testing)
CBT (Computer-Based Testing)
Students take tests on a computer; subjective answers are evaluated online
The system is multi-tenant (multiple organizations/universities) and multi-campus.

Evaluation Flow Summary (Text)
Evaluation Flow Summary (Text)
1. SETUP
   Admin creates exam_informations
     → with test_details[] (one entry per course, each with a mode)
     → links to yearly_masters (which student batch)
     → optionally links to moderation_rule_sets
2. PRE-EVALUATION
   Admin uploads synoptic PDFs to Azure → stored in exam_informations.test_details[].blueprint_details
   Admin creates marking_pallets → defines max marks per question → frozen before evaluation starts
3. OSM FLOW
   Scanner uploads Scanned_Scripts
     → tagged with exam_details, course_details, test_details._id, candidateId
   Admin runs Roster Engine → creates distribution_rosters (evaluationType = "primary")
     → each roster: evaluatorId + assignedScripts[] + scriptCount
   Faculty opens script → fetches PDF (Azure SAS URL) + marking pallet
   Faculty saves marks → evaluation_results upserted
     → roster auto-transitions: pending → in_progress → completed
4. DATA ENTRY FLOW
   Faculty sees test list (getDataEntryTests, entryType = data_entry)
   Faculty selects test → sees student list + marking pallet
   Faculty saves marks → evaluation_results upserted with entryType = "data_entry"
5. MODERATION
   Admin applies moderation rules (applyModerationAndCreateRosters)
     → qualifying scripts get new distribution_rosters (evaluationType = "moderation")
   Moderator evaluates → second set of evaluation_results
6. PUBLICATION
   getPublicationData: merges evaluation_results (offline) + cbt_marks (online)
     → finalScore = moderationScore ?? primaryScore  (offline)
     → finalScore = totalMarksObtained              (online CBT)
